# Changelog

## Unreleased — shared toolchain and native ownership correction

- Restored the personal Mac Home Manager Rex binding and user-owned init loader, and removed the obsolete Orca Serve sync LaunchAgent declaration. The candidate generation builds and its generated Rex Lua passes `rex config check`; no live activation or Tailscale Serve change is claimed.

- Added `jj` to the shared Darwin/Linux Nix core package set (current lock: `0.42.0`) and linked tracked workspace lifecycle instructions into the default OMP user profile only when enabled. The rules guide ownership, safe reuse, retention and cleanup decisions; they do not convert repositories, change signing, automatically enforce cleanup, alter Rex, or activate Home Manager.

- Replaced the Home Manager Hunk theme and review-note exporter with native `tuicr`, owned by the opt-in, manually applied macOS `pkgs/Brewfile` (not `scripts/install.sh` or Home Manager). Reviews now use tuicr's built-in save, clipboard and resume workflow; existing saved reviews and live apps are untouched.
- The shared Nix profile now includes the OpenSSH client and its command check on macOS and Linux, so non-login headless starts do not depend on the host providing `ssh`. This does not change the headless profile's HTTPS Git authentication or provision an SSH agent.
- The Rex access smoke now requests a Kubernetes SubjectAccessReview for `system:anonymous` with the `system:unauthenticated` group, instead of using impersonating `kubectl auth can-i` and treating its output as an anonymous denial. API errors or an allowed decision still fail closed.

- Neovim now enables its configured LSP servers directly; Home Manager owns the LSP, formatter and build executables through one `extraPackages` list shared with the user profile. The wrapper exposes them even without a developer-shell PATH on the shared Mac, headless Linux and Rex profiles. Lazy.nvim remains the plugin owner; standalone users supply their own executables. Removed Mason's installation/fallback path without changing nixd's alejandra formatting or Conform routing.
- Unified writable native OMP, Pi, Claude, OpenCode, Codex and Vercel installation under `ai/bootstrap.sh install|update|check`; Home Manager selects enabled tools via `~/.config/dev-config/native-tools` and installs missing tools at activation without upgrading existing ones. Skills fill missing per-tool links, preserve physical user directories and unmanaged entries, and advance only recorded links still pointing at their recorded target.
- Shared Darwin/Linux system commands and checks come from `pkgs/tool-checks.json`; optional Mac host extras live in `pkgs/Brewfile`. Existing `helm@3` is preserved, not the desired fresh-host pin; held third-party taps/casks are not installed without an explicit trust decision. Nix source revisions are locked in `flake.lock`, while native CLIs and MCP stdio launchers float on explicit update/install rather than claiming automatic latest everywhere.
- MCP has profile-selected Claude/OMP/Codex targets and an explicit `op` or `env` credential source, without fallback. Required missing auth or a missing launcher aborts before replacing working configuration. Native Vercel owner OAuth is separate from the community MCP child: the `env` input is `VERCEL_MCP_TOKEN`, rendered only as child `VERCEL_TOKEN`; no identity is inferred from CLI presence.
- The shared headless profile uses HTTPS with the existing GitHub CLI credential helper rather than assuming a Mac SSH agent; Rex can activate this same flake directly at startup without rebuilding a tooling image.
- Home Manager configures MCP after native bootstrap and resolves launchers from its activated package profile, including non-login headless starts without an inherited developer-shell PATH. MCP activation also retains native host paths (including macOS Homebrew) after Home Manager resets PATH; required missing launchers still fail before replacing working configuration. The generated PATH passed an isolated Codex-only renderer smoke, not live activation.
- Yazi's declared preview and archive dependencies are exposed in the user profile as well as its private wrapper; PDF previews select `poppler-utils`, not the Poppler GLib library without CLI tools.
- The existing Rex PostgreSQL `postgres` owner profile was confirmed elevated superuser, not a least-privilege or collaborator credential; no roles, grants, or credentials were changed. Native/Pi/Claude/MCP regressions and 22 DevPod Helm credential-isolation checks passed. Mac/headless Home Manager derivations evaluated; Linux private-home activation, all 72 shared command contracts, six fresh native installations, private MCP files and real isolated Rex RPC passed against source `59ef5d1988a37007f7bdd03dc23c96dd437ed57f`. No live profile activation, image promotion or provider-authorization equivalence is claimed.
